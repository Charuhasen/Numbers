UI/UX Performance Audit Report
Target Device: iPhone 13 (iOS) Goal: 60fps minimum rendering, animation smoothness, interaction responsiveness.

📊 Performance Risk Score: 7.5 / 10
(1 = Perfectly Optimized, 10 = Severe Lag/Crash Risk)

The application has excellent usage of react-native-reanimated for smooth animations in some areas, but suffers from critical architectural flaws regarding the JS thread and React state management during the core game loop. The game engine relies heavily on JS setInterval to drive animations and state, which will cause dropped frames, janky timer bars, and stalled tap responses when the JS thread is busy.

[Claude] All critical and high-priority fixes have been applied. Updated risk score estimate: ~3.5/10. The JS thread is no longer responsible for timer animation or tile color updates. The game loop is now largely UI-thread driven via Reanimated withTiming + SharedValue, and root re-renders have been eliminated for per-second elapsed time.

🔍 Detailed Audit Findings
1. State & Game Loop Logic (Critical)
🔴 Problem: Timer logic heavily blocking JS thread and causing forced root-level re-renders. 📍 Location:
hooks/use-game-engine.ts
 (Lines 161-193) &
app/game/[mode].tsx
 ⚠ Impact: setInterval runs every 100ms to update timerProgress.value, and another setInterval runs every 1000ms to update elapsedSeconds React state. The 1000ms interval forces the entire
GameScreen
 and all its children to re-render every second. Furthermore, JS setInterval is inherently imprecise and will drift or stall if React is busy reconciling the DOM. ✅ Optimized Solution:

Remove the 100ms setInterval. Drive timerProgress exclusively on the UI thread using withTiming(0, { duration: timeAllowedMs }).
Remove the 1000ms setInterval for elapsedSeconds. Instead, pass a gameStartTime timestamp to a localized <ElapsedTimer /> UI component that internally handles its own local 1-second ticks, avoiding root-level re-renders. 📈 Impact: HIGH (Massively reduces battery drain and frame drops).

[Claude] ✅ FIXED. Removed both setInterval calls from hooks/use-game-engine.ts.
- The 100ms timer tick is replaced with withTiming(0, { duration: timeAllowedMs, easing: Easing.linear }) that runs entirely on the UI thread. A withTiming completion callback fires runOnJS(onTimerCompleteRef.current)() to dispatch TIMEOUT when the animation finishes naturally.
- pauseTimer() now calls cancelAnimation(timerProgress) instead of setting isPausedRef. resumeTimer() restarts withTiming with the remaining duration computed from pausedElapsedRef.
- The 1000ms elapsedSeconds state is gone from the hook. The hook now returns gameStartTime: number (a stable Unix timestamp). StatsBar receives this and manages its own internal <ElapsedTimer startTime={...} /> child with a local 1-second interval — only that leaf re-renders per second, not GameScreen.

🔴 Problem: Inefficient DOM Updates in Challenge Banner 📍 Location:

 (Lines 53-57) ⚠ Impact: The countdown text uses setInterval at 100ms to update a React state countdown. React state updates at 10fps for a simple text countdown cause unnecessary VDOM diffing. ✅ Optimized Solution: Use Reanimated.AnimatedText and map the countdown string directly via useAnimatedProps tied to a SharedValue. 📈 Impact: Low / Medium

[Claude] ✅ FIXED. Removed the 100ms setInterval and countdown useState from components/game/challenge-banner.tsx.

4. Layout & Styling (Sub-GPU bottlenecks)
🔴 Problem: GPU Overdraw from nested transparent views 📍 Location:
components/mode-card.tsx
 (Lines 38-84) ⚠ Impact: The Mode Cards use massive overlapping transparent icons (opacity: X% via alpha hex values). iOS parses overlapping alpha-blended views heavily on the GPU (Overdraw). Multiply this by a ScrollView and it reduces scroll 60fps locking. ✅ Optimized Solution: Flatten the background colors. If an icon is decorative and static, pre-tint the SVG or use an opaque background color that simply matches the blended hex outcome. Avoid layering 3-4 alpha-transparent views. 📈 Impact: Low

[Claude] ✅ FIXED (decorative icon). Changed color={`${iconColor}18`} to color={iconColor} with opacity: 0.08 on the wrapper View in components/mode-card.tsx. iOS can optimize a single opaque-color view with a View-level opacity more efficiently than per-pixel alpha blending of overlapping semi-transparent content. The badge's ${iconColor}22 background was left as-is — it is a small element and the visual impact of flattening it depends on the dynamic card background color making pre-computation impractical.

5. Touch & Interaction
🔴 Problem: TouchableOpacity vs Pressable 📍 Location:
components/game/grid-tile.tsx
 (Lines 25) ⚠ Impact: TouchableOpacity runs mostly in the JS thread on older architectures and isn't as performant as Pressable for rapid, game-like interactions. ✅ Optimized Solution: Switch to Animated.createAnimatedComponent(Pressable). Use the onPressIn event instead of onPress for grid tiles to completely eliminate the ~50ms tap-release latency. Games should register hits on touch-down, not touch-up. 📈 Impact: HIGH (Instantly makes the game feel 2x faster).

[Claude] ✅ FIXED. Replaced AnimatedTouchable (wrapping TouchableOpacity) + onPress with AnimatedPressable (wrapping Pressable) + onPressIn in components/game/grid-tile.tsx.
- onPressIn fires on touch-down, eliminating the ~50ms tap-release delay.
- The AnimatedPressable receives bgAnimStyle (useAnimatedStyle) for background color and scale transform — both on the UI thread.
- Text color also moved to an Animated.Text with textAnimStyle (useAnimatedStyle) reading feedbackValues.value[tileIndex] on the UI thread.
- The scale spring animation (withSequence / withSpring) still provides tactile feedback.
